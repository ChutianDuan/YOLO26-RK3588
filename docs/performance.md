### 三模型 split 对比与各 10 分钟连续长测

2026-10-19 完成 FP16、INT8、Hybrid 的统一条件复测：单路相同交通 JPEG 回放，输入约 **30.107 FPS**，MPP 解码为 NV12 DMA-BUF，RGA letterbox 到 RGB 800×608，conf=0.25、`--detect-fps 0`，三个独立 Context 分别绑定 Core0/1/2；关闭预览，保留画框和跟踪。所有硬件进程串行运行，编译、固定输入跨核心一致性及 12 次运行检查均通过。

短测每模型三轮，每轮完整回放 1210 帧，按 FP16→INT8→Hybrid、INT8→Hybrid→FP16、Hybrid→FP16→INT8 轮转。排除前 90 帧和末尾 30 帧后，三轮平均有效检测 FPS 分别为 **13.81 / 30.11 / 30.11**。随后每模型用同一进程、同一套 Context 连续运行，帧序号和时间戳不重置；每次输入 18066 帧，源时间跨度约 **600.03 秒**。

下表为连续长测结果。FPS、RSS、PSS、CPU、NPU 负载为排除前 30 秒及末尾 30 帧后的稳态统计；推理帧数为全程计数，温度为全程采样峰值。

| 模型 | 完成推理 / 输入帧数 | 有效检测 FPS | RSS 均值 | PSS 均值 | CPU 均值 | NPU Core0/1/2 均值 | NPU 最高温度 |
|---|---:|---:|---:|---:|---:|---|---:|
| FP16 | 8658 / 18066 | 14.42 | 252.21 MiB | 244.60 MiB | 193.89% | 38.96% / 41.12% / 41.15% | 53.62°C |
| INT8 | 18066 / 18066 | 30.11 | 128.48 MiB | 120.89 MiB | 30.53% | 40.73% / 41.66% / 41.96% | 51.77°C |
| Hybrid | 18066 / 18066 | 30.11 | 146.17 MiB | 138.56 MiB | 37.93% | 46.43% / 47.75% / 47.98% | 51.77°C |

CPU 以单核 100% 计，NPU 各核负载来自驱动窗口采样。FP16 全程完成 8658 次推理，其中 8655 个结果被接受，3 个迟到结果被丢弃，另有 9407 帧在推理等待槽被替换、1 帧在退出时舍弃。INT8 与 Hybrid 均完成并接受全部 18066 帧，无推理等待丢帧及迟到丢弃。三组视频输出均为 18066 帧，输出帧率与实际检测更新速度分别统计。

长测稳态首尾各一分钟的 RSS 中位数变化分别为 **0 / 0 / +0.125 MiB**，PSS 中位数变化分别约 **+0.066 / +0.039 / +0.035 MiB**；FD 中位数均为 46 个。Hybrid 的 RSS 小幅增加后保持稳定。RSS、PSS 与可识别 DMA-BUF 占用存在重叠，不能直接相加；DMA-BUF 按唯一缓冲对象去重，完整分布见报告。

在这组输入下，Hybrid 保留了接近 INT8 的文件大小，并完成约 30 FPS 的逐帧检测，CPU、内存和 NPU 负载略高于 INT8。**30.11 FPS 受输入速率限制，本次未测最大吞吐或 Hybrid mAP**；固定输入一致性与 10 分钟资源趋势不能替代工业精度评测或更长期稳定性验证。

### FP16 / INT8 检测精度与早期 split 对比

2026-10-19 板端复测：单路交通视频、三个独立 Context 分别绑定 Core0/1/2，MPP→NV12→RGA→RKNN，统一跟踪，关闭预览但执行画框。两种模型的性能各跑三遍完整 1210 帧；精度另在相同 202 张标注图上测试，均完成全部标注帧，避免速度导致的丢帧影响模型 AP。

| 早期复测模型 / 指标 | FP16 split | INT8 split |
|---|---:|---:|
| 六类 mAP50 | 49.91% | 29.04% |
| 六类 mAP50–95 | 24.37% | 8.41% |
| 工作点 F1，conf=0.25 / IoU=0.5 | 58.04% | 35.85% |
| 推理阶段均值 | 215.75 ms | 44.02 ms |
| 源时间到检测结果 P95 | 258.24 ms | 53.98 ms |
| 输出所用检测数据年龄 P95 | 341.49 ms | 75.57 ms |
| 有效检测结果更新 FPS | 13.76 | 30.11 |
| 视频输出 FPS | 30.11 | 30.11 |
| 实时轨迹 IDF1 | 0.3413 | 0.2422 |
| 每遍峰值 RSS 的均值 | 252.16 MiB | 128.33 MiB |

推理阶段包含输入绑定、Runtime 执行和输出获取/转换，不是纯 NPU 时间。性能在排除前 90 帧、末尾 30 帧的固定源时间窗内统计；表中均值和 P95 为三遍统计量的算术平均。FP16 三遍有效检测更新为 12.71～14.47 FPS，INT8 均约 30.11 FPS；后者受输入速率限制，不代表已测得最大吞吐。输出线程用轨迹预测维持视频，因此两者输出都约 30 FPS，不能把输出 FPS 当成实际检测 FPS。

这组 AP 来自同一 BDD100K training 片段的六个有真值类别，使用先拉伸到 800×600 的 JPEG 夹具，再由 MPP/RGA 处理；原始检测框恢复到 1280×720 评分。它不是独立工业测试集，也不能与下方历史原视频 AP 直接合并。该组评测中 FP16 精度更高但检测更新较慢；INT8 更新更及时，mAP50 下降约 20.87 个百分点。实际摄像头采集、曝光到显示以及三路独立视频未在本组复测。

### 模型精度与量化代价

| 历史模型 / 预处理 | 六类 mAP50 | 六类 mAP50–95 |
|---|---:|---:|
| 主机 FP32 / OpenCV | 48.58% | 24.48% |
| 板端 FP16 / RGA | 48.83% | 24.30% |
| 板端 INT8 / RGA | 28.27% | 9.99% |

数据为 BDD100K **单条 training 序列**，1210 源帧、202 个标注时刻，六类有普通真值。评测采用候选下限 0.001、101 点 AP、忽略 crowd/distractor；固定阈值 P/R/F1 读取 conf=0.25/IoU=0.5 的 `operating_point`，不能拿 0.001 候选层的外层 P/R 冒充工作点。交通灯/标志没有该 MOT 标注，不纳入精度统计。

FP32 是另一台主机的历史结果，没有板端 FP32 性能数据。旧标准输入流程中 FP16/INT8 推理阶段均值约 143.453/42.811 ms，调用耗时比约 3.35；该组发生在 FD 输入改造之前，不能直接作为当前 FD 链路的加速比例。INT8 在该片段上存在明显的量化精度损失，后续 Hybrid 已采用 PTQ 后逐层误差对比、关键层保留 FP16 的方式进行优化；这里的历史 AP 不代表 Hybrid 的精度结果，校准集覆盖与工业场景分布仍需继续验证。

### 跟踪与瓶颈

历史文件流程中，原分辨率 RGA 灰度准备下 FP16/INT8 的 Flow 均值约 64.982/44.605 ms，处理 FPS 为 12.63/17.10；RGA 半分辨率对应 38.864/26.190 ms、18.90/24.96 FPS。这是后续 LK 对照实验，各一次异步运行，与更早的三次模型对比不是同一组数据。

实时交通夹具的 default/split 跟踪 IDF1 为 **0.2332/0.2422**，MOTA 为 **-0.0300/-0.0498**，ID 切换 187/230。吞吐提高并未证明跟踪 ID 精度达标。两种模式都覆盖 202/202 标注时刻；预处理和调度与 LK 离线基线不同，不能把变化完全归因于 Kalman 或核心模式。

已有外部 FD 合成视频长测输出 3000 帧、仅推理 197 次，处理 72.425 FPS；输入仅 320×240，含 LK 补帧，不能称为 72 FPS 的全帧模型检测能力。
