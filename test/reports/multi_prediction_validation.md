# 四路视频：ByteTrack 原生预测与异步 RKNN 校正

生成时间：2026-10-21T00:40:32.170800+00:00

本次四路入口只使用已有 ByteTrack/Kalman，不运行 LK 或其他图像光流。三个 NPU Worker、公平调度、RGA 输入及 BGR 帧池沿用已验证实现。

## 行为与参数

- RKNN 结果在检测源帧的媒体时间执行两阶段关联和 Kalman 测量更新。输出侧从不可变快照调用同一原生 Kalman 状态转移/过程噪声，按画面真实时间预测中心、尺寸和协方差。显示预测不回灌为测量，不推进检测侧时钟。
- `--detect-fps 0` 保留全速竞争；正值限制每路正常检测请求频率，取样量化和不可用源帧会降低实际频率，EOF 补交最后一幅已发布画面。本次周期检测设置为8，属于请求频率受限，不能用于推断 NPU 极限。
- `--track-max-age-ms 500` 是默认有效期，支持1～1000 ms。每个框以最后一次真实匹配为起点计时；预测和较新的未匹配检测结果都不能延长它。短时失配保留 ID，过期隐藏。
- JSONL 额外记录逐框真实检测帧号/年龄、预测跨度、tracked/lost 状态、中心标准差，以及每幅画面采用新检测快照和预测框的数量。标准差未经业务校准，检测分数不等于预测质量。

## 构建、运行与正确性

- 系统 C++17、GCC/CMake/Ninja，两个工程均以4线程构建成功。正式与测试二进制字节一致；`production_binary.json` 保存 SHA256，并确认可执行文件未链接光流符号。
- 最终9项回归全部通过：multi_scheduler、multi_recorder、multi_prediction、multi_video、core、hardware、live_core、live_npu、cli。见 `final_regression.log`。
- 新增测试验证原生预测与检测侧内部 Kalman 的均值/协方差一致，重复帧不重复推进，检测校正保留 ID，短时遮挡、真实检测年龄、过期隐藏、未来/旧结果约束和通道隔离。
- 实际四路固定画面继续与三核串行推理比较，坐标误差≤1 px、分数误差≤0.01；覆盖不同FPS/长度/分辨率、旋转视频、EOF、录制、写盘/解码/推理失败及SIGINT。新增4次/秒请求与100 ms显示有效期集成检查。
- `acceptance_check.py` 对本次10次板端运行的所有结果检查路由、核归属、检测去重、快照水位、轨迹ID、逐框真实检测年龄和预测计数，见 `acceptance.json`。

## 边界

本次为120秒连续运行，原四路基线的十分钟测试属于先前版本，不能当作本次版本的十分钟证据；历史见 [四路基线](multi_video_validation.md)。真实图形会话窗口未验收。真实交通轨迹没有逐帧真值，本次不声明 MOT 精度或新目标/急转场景的预测精度达标；Kalman 只利用已有状态，急转、遮挡和新目标仍依赖后续 RKNN 测量。

没有修改系统、SDK、驱动、设备权限，也没有增加跟踪线程、灰度图池或其他硬件预处理。文件解码仍为CPU OpenCV/FFmpeg，RGA前仍有CPU上传复制，不是端到端零拷贝。
