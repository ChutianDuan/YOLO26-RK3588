## 三路与四路实测

同一交通 MOV 由独立解码器分别打开，解码后1280×720、约30.115 FPS，三套 INT8 800×608 RKNN Context 分别绑定 Core0/1/2。软件解码、CPU BGR 上传、RGA、RKNN、跟踪和 JSONL 均在同一进程。短测各20秒，长测600秒；稳态排除前3秒及末尾1秒。

| 负载 | 每路检测 FPS | 总检测 FPS | 每路输出 FPS | 最小/最大检测 FPS | CPU均值 % | RSS峰值 MiB |
|---|---|---:|---|---:|---:|---:|
| 三路 / 不录制 | 17.49 / 17.56 / 17.63 | 52.68 | 30.06 / 30.06 / 30.06 | 0.9925 | 336.08 | 219.10 |
| 三路 / 录制 | 16.95 / 16.49 / 16.88 | 50.32 | 30.11 / 30.11 / 30.11 | 0.9725 | 520.91 | 230.23 |
| 四路 / 不录制 | 13.37 / 12.83 / 13.43 / 13.10 | 52.73 | 29.92 / 29.92 / 29.92 / 29.92 | 0.9554 | 440.63 | 245.36 |
| 四路 / 录制 | 12.49 / 12.23 / 12.49 / 12.49 | 49.70 | 30.10 / 30.10 / 30.10 / 30.10 | 0.9787 | 670.74 | 259.24 |
| 四路 / 十分钟 / 不录制 | 13.17 / 13.18 / 13.31 / 13.02 | 52.67 | 30.11 / 30.11 / 30.11 / 30.11 | 0.9784 | 443.44 | 245.98 |

检测 FPS 按实际完成推理计算，零目标结果也计数；输出 FPS 包含复用画面和跟踪预测。源视频解码和等待槽都会按实时策略丢弃过期帧，不能将输出 FPS 理解为逐帧检测率。基准使用时长限制，`status=stopped / stop_reason=duration` 属于正常到时停止。

## 十分钟公平性、延迟与资源

运行 600.035 秒，共完成 **31,601 次实际推理**。所有检测事件数量与已派发/已接受计数一致，没有重复派发、结果串路、过期结果回退或结果队列丢失。

| 通道 | Core0 | Core1 | Core2 | 完成检测 | 派发占比 | 结果延迟 P95 ms |
|---|---:|---:|---:|---:|---:|---:|
| 0 | 2731 | 2567 | 2600 | 7898 | 24.99% | 148.01 |
| 1 | 2717 | 2606 | 2584 | 7907 | 25.02% | 147.41 |
| 2 | 2747 | 2585 | 2651 | 7983 | 25.26% | 147.06 |
| 3 | 2723 | 2534 | 2556 | 7813 | 24.72% | 148.39 |

- 全部滑动约5秒检查窗口内，每路至少新增 **61 次检测**；每路等待槽/在途上限均为1，结果队列峰值不超过64。
- 稳态 FD 始终为 **31**；进程 RSS 为 **244.73～245.98 MiB**，前/后60个稳态样本均值为 245.55/245.98 MiB。
- NPU Core0/1/2 平均负载为 **84.62% / 82.01% / 82.71%**；NPU 热区采样最高 **58.23°C**。
- 四路录制短测分别写出 603/603/603/603 帧，录制阶段 P95 为 25/25/26/26 ms。
- 长测每路约18,069个源帧，约4,967～4,986帧在解码落后时跳过发布；剩余帧的检测等待项也会被较新帧替换。帧池无空闲槽丢弃为0。

这组结果描述当前软件解码链路的实测吞吐，不等于纯 NPU 最大吞吐，也不构成长期无泄漏保证。CPU 单核=100%；RSS/PSS不可相加，可能不完整覆盖设备内部内存。未重新评估模型 mAP、召回率或工业业务精度，也没有预设业务 FPS 达标门槛。

## 运行与证据

直接运行方法见 [四路视频说明](../../yolo_run/video/MULTI_VIDEO.md)。新增录像使用系统 OpenCV JPEG85 编码与现有 libavformat AVI 封装，控制 CPU 开销，并保留分数帧率和写盘错误。CPU 上传仍然存在，不宣称端到端零拷贝。
